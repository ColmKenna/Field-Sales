## Approved transition table (guards)

| From | Action | To | Guards |
|---|---|---|---|
| In Progress | Change a line quantity, Save | In Progress | Quantity follows the product's rules on the current snapshot; captured price, unit, snapshot kept |
| In Progress | Remove a line (not the last) | In Progress | — |
| In Progress | Remove the last line | deleted | Asks "Remove the last line and delete this order?"; cancel keeps it |
| In Progress | Mark Ready to Send | Ready to Send | ≥1 line (WI-038) |
| In Progress | Delete order + confirm | deleted, nothing sent | confirmation |
| Ready to Send | Reopen | In Progress | not Needs Attention; **not claimed by an upload** |
| Ready to Send | Delete order + confirm | deleted, nothing sent | same as Reopen |
| Ready to Send | Edit lines | not allowed | Reopen first |
| Ready to Send (claimed) | server confirms | Sent | WI-039 |
| Ready to Send (claimed) | refused 400/409/413 | Needs Attention, claim cleared | WI-042 |
| Ready to Send (claimed) | 401/403, or request provably never reached the server (DNS/connect/TLS failure, `HttpRequestError`) | Ready to Send, claim cleared | |
| Ready to Send (claimed) | lost mid-request, timeout, 5xx, unreadable receipt | Ready to Send, claim **kept** | locked until a later Sync gets an answer |
| Needs Attention | anything but WI-042's Open / re-mark / Delete | refused | D2 |
| Sent | anything | refused, no controls | |

**Upload claim:** the uploader claims each item under the same per-rep gate `OrderStore` uses (`Gates` keyed by `UnsentPath`), and only if the
saved body still equals the queued body. A changed or deleted item is skipped and not counted as "not sent". Reopen/edit/delete check the claim
under the gate. Hence no path changes an order after its upload has started.

## Approved decisions (D1–D6)

| D4 | Order at a shop no longer assigned: reopen, change, remove and delete allowed; adding a product still needs assignment (WI-038). (inferred) |
| D5 | Product missing from today's snapshot: line can be removed, quantity can't change (step/minimum aren't stored on the line). (inferred) |
| D6 | Quantity change keeps the captured price; breaks are E6 (WI-065/066). (inferred) |

Screen (step 3): `NewOrder.razor` gains `/locations/{LocationId}/orders/{OrderId}` for an existing order. In Progress: per line Change (inline
field prefilled with the current quantity; WI-045 stepper for measures) and Remove; footer Delete order. Ready to Send: notice, Reopen, Delete order,
Close. Claimed: "Sending this order wasn't confirmed. Sync again before changing it." and no change controls. Sent: read-only lines, no controls.
