## Agreed test matrix (Human-Led; the developer confirmed 1–3)

Put the tests in `FieldSales.Identity.Admin.Tests/Infrastructure/TemplateAdoptionBaselineTests.cs`,
using the card's `Should_X_When_Y` names:

1. `Should_StartTheIdentityHost_When_ThePinnedTemplateIsConfigured`: a Development host on new
   SQL Server databases (reuse `Task02SqlServerFactory` and the approach in
   `DevelopmentMigrationSqlServerTests.FreshDevelopmentHost_...`). All three contexts have no
   pending migrations, and `/.well-known/openid-configuration` returns 200 with an issuer.
2. `Should_DenySecurityAdministration_When_TheUserLacksSysAdmin`: a Theory over `/Admin`,
   `/Admin/Users`, `/Admin/Clients` and `/Admin/Roles`. The non-admin identity is redirected to
   `/Account/AccessDenied`, and anonymous requests redirect to `/Account/Login`. Use the
   `AdminWebFactory` `X-Test-Auth` header, as in `AdminAuthorizationIntegrationTests`.
3. `Should_KeepRevokedAdministrationRevoked_When_TheHostRestarts`: persistent SQL Server databases,
   a Development host seeds `admin@sales.local`, demote it, dispose the host, start a new host on
   the same databases, and assert the user is still not `SysAdmin`.
3b. *(optional; the developer's "confirm" didn't clearly cover it, so ask at the Increment 3 stop)*
   Characterise that a **deleted** `admin@sales.local` is recreated with SysAdmin on the next
   **Development** start (`SeedData.EnsureUserAsync` creates any missing user), and that outside
   Development nothing is seeded.

Existing template tests already partly cover 2 and 3 (`AdminAuthorizationIntegrationTests`,
`AdminBootstrapTests`), but `AdminBootstrapTests` never actually restarts the host; it only opens a
second DI scope.
