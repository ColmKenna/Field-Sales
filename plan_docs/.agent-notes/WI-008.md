## Increment 2 implementation

- `POST /catalogue/products/{id}/base-prices` accepts BasePrice and EffectiveFrom, appends one
  dated row through Product.AddBasePrice and returns 201 with the saved entry. Missing products
  return 404. Missing/malformed dates or invalid amounts return 400. Amount validation preserves
  the initial-price rules: exact decimal, non-negative, two decimal places, decimal(18,2) bounds.
- The existing HeadOfficeCatalogue policy guards the route: current role, valid bearer token,
  audience and fieldsales.api scope. No new permission, table or migration is introduced.
- A duplicate date returns 409 with field EffectiveFrom and the exact dated message
  "A price already starts on 1 Nov 2026 — edit it instead". The existing composite database key
  settles concurrent saves; the losing request receives the same field/message. Existing rows
  are unchanged, including for rejected requests.
- CatalogueApiClient.AddProductBasePriceAsync uses the server-held bearer token, sends the exact
  decimal amount and calendar date, and retains API field errors for the later form. Missing and
  unavailable outcomes remain distinct. This increment adds no website handler or form.
- Five SQL/API cases cover host restart and persisted past/future entries, the Dublin date at
  23:30 UTC, sequential and concurrent duplicates, invalid requests and denied writes. The
  concurrent test holds both saves after duplicate lookup, forcing the SQL conflict path.
- Five BFF client cases verify the token/payload and responses for success, duplicate date,
  invalid date, missing product and denied write. Browser cookie expiry remains the later form's
  scenario; this increment covers expired API tokens and role removal without any write.
