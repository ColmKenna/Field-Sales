## Approved decisions

- **D1 Rule (developer):** history = the product's quantity on whichever of the shop's last 3 accepted orders contained it. At least
  **2** such orders, else no marker. Usual = **median** (two orders: their average). Marked when the line's quantity is **more than
  3× usual** (strictly). No absolute floor. High only. One pure function `QuantityMarker.For(line, history, step)` in Tablet.Core.
- **D2 Text:** "Usually about 48 here"; N rounded to a whole number for Each, to the product's step for measured products with the
  unit ("Usually about 2.5 kg here"); halves round up (47.5 → 48). The 3× test uses the exact median.
- **D3 Units:** past quantities in a different unit from the line are ignored and don't count towards the 2.
- **D4 Snapshot 1.5** (minor): each `recentOrderLines` row gains optional `quantities: [{ quantity, unit }]`, newest first, one per
  recent accepted order containing the product (summed if it appears twice). Tablet format 4 → 5 with `recent_order_quantities` by
  an upgrade step. Import refuses quantities on a snapshot older than 1.5, a 1.5 row without quantities, a quantity ≤ 0 or an
  empty unit. Size ≈ 24,000 rows × 25–60 bytes (0.6–1.4 MB plain). Owner reviews at the checkpoint/plan.
- **D5 Where:** order-entry lines ("On this order") while the order is In Progress or Ready to Send; text under the line; not on
  Sent, Sending or Needs Attention. Never blocks Mark Ready to Send; no acknowledgement.
- **D6 Out of scope:** Sync's order review, the Large annotation (E28), low markers, order acceptance (WI-067: until then real
  tablets show no markers, as with "Ordered recently").
- **D7 Finish:** push, PR, merge after CI (merge commit, branch kept), update local main.
