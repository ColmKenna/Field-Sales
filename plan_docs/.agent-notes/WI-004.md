Parent criteria name product breadcrumbs and unchanged orders/calls. ## Approved decisions and scope

- Use the predecessor's .NET 10/Aspire single staff website, API role boundary, SQL Server and EF Core. Categories have stable GUID IDs, optional parent IDs and sibling-unique names; depth has no cap. Derive breadcrumbs on read.
- Do not persist or replay rejected/expired category form submissions. A protected write is denied before it changes storage.
- The approved catalogue database placement is `FieldSales.Api` with a separate `CatalogueDb` context and Aspire SQL resource. The existing `StaffWebDb` is website session storage.
- Record, but do not implement, the later staff-directory rep-to-manager reporting line. Keep tablet language, pricing day boundary and Visit Planning administrator-role questions with their later items.
- The H-15 single-category view and breadcrumb navigation are the proposed UI direction for this slice. Review the actual page design before the UI increment.

## Approved Human-Led scenario matrix

| Candidate | Observable intent |
|---|---|
| `Should_OpenCategoryArea_When_HeadOfficeRoleIsHeld` | A signed-in Head Office User can read the category page. |
| `Should_DenyCategoryReadAndWrite_When_HeadOfficeRoleIsMissing` | A Field Salesperson and a Sales Manager without Head Office User cannot read or change categories. |
| `Should_PersistRootAndNestedCategories_When_ApplicationRestarts` | Creation through the site remains after a restart. |
| `Should_ShowFullBreadcrumb_When_SixthLevelIsAdded` | Six levels are accepted and the full path appears; the domain has no depth cap. |
| `Should_DistinguishSameNamedLeaves_When_ParentsDiffer` | Lotions under Suncare and under Body Care are distinct IDs and display distinct full paths. |
| `Should_RefreshDescendantBreadcrumbs_When_AncestorIsRenamed` | Renaming Lotions to Lotions & Creams changes each descendant's derived path while stable category IDs and parent references remain unchanged. |
| `Should_NotSaveCategory_When_StaffSessionExpiresOrRoleIsRemoved` | A stale form POST is denied, writes nothing, and is not replayed after sign-in. |

No Product, Order, or Call schema will be added solely to mirror the source's future-record assertion. Tests for those actual records belong with their introduction.
