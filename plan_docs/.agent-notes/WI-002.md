## Current state

**WI-002 is complete.** `FieldSales.Web` provides I-01 entry, redirects
to the adopted identity password page, returns rejected staff credentials to the I-01 retry state,
and serves role-protected rep, manager and head-office landings. Sign out ends the BFF cookie
session and invokes OIDC sign-out. The BFF stores encrypted tickets and tokens in `StaffWebDb`,
keeps only an opaque key in the browser cookie, and refreshes API tokens server-side. Its staff
workspace calls `FieldSales.Api` `/staff/session`; the API checks issuer, audience, scope and a
business role. Development applies the migrations; production uses the `staff-web` migration
bundle and requires a Data Protection certificate. `StaffWebDb` also stores the last selected
area by identity subject. The destination is checked against current role claims whenever it is
selected. Single-area staff go directly to that area; multi-area staff without a permitted saved
area see I-02, which lists only their permitted choices. Area navigation stays in the same session.

The full solution builds with 0 warnings. The full .NET suite passes 1002/1002, 0 skipped
(identity/admin 975, Web 26, API 1), including the Docker-backed SQL Server tests. Admin UI
passes 18/18 and console status-store passes 11/11. EF reports no pending model changes, and
all four migration bundles build. The ten approved Human-Led scenarios are verified below.
