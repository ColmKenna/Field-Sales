## Approved decisions

- **D1 Link direction:** the Call carries optional `orderId` (written only when set) — the order its products were added to. The Order
  body is unchanged; neither contract changes version. Server: nullable `ReceivedCalls.OrderId`, no FK (the order may upload later or
  never), via a migration.
- **D2 Find-or-create:** target = the call's linked order if still In Progress (not Sending / Needs attention / Ready); else this rep's
  most recently saved In Progress order at the shop; else a new order. Choose-and-add in one step under the per-rep `OrderStore` gate.
  The draft keeps the order id; the button is busy-locked while saving. If the linked order was marked Ready or deleted elsewhere, the
  next add re-finds/creates and the link moves.
- **D3 In person:** a Low tick on every row (Not checked rows too, per wireframe), replacing WI-050's read-only note. Ticking Low shows
  Add to order. Unticking Low In person keeps the count (0 is a real count there); Phone keeps WI-050 D6 (Low off clears Out).
- **D4 Phone:** Add to order is active on every row (S8) and does not mark Low. A row only on the order isn't saved as a stock entry.
- **D5 "On order (N)":** replaces Add to order wherever it would show when the product is on the call's order (linked or found),
  including lines added from order entry. Measures show the unit ("On order (2.5 kg)"). Unticking Low leaves the line (S4, T7.8).
- **D6 Popover:** name; "counted 3" / "not counted"; empty quantity (never pre-filled); "€8.95 · list price" (per kg for measures);
  Cancel, ✕, Add to order. Add unavailable until valid; messages from `QuantityRules` ("Enter a quantity of 1 or more",
  "Enter at least 1.0 kg in steps of 0.5 kg"). No price → existing no-price message, Add unavailable. Store refusals shown inside.
  Closes on add. Wording "list price" on screen; saved lines keep the contract's "Base price".
- **D7 Reusable component:** `Components/Shared/QuantityPopover.razor` (product, recorded-count text, busy, error, add callback, cancel
  callback, a slot under the price for T-6.5.1's break prompt). The Low tab (T-5.1.4) reuses it as is.
- **D8 Leaving unsaved** keeps lines added to the order (T7.8); the leave dialog adds "Lines added to the order stay on it." when any.
- **D9 Server:** accepts a non-empty `orderId`; refuses an empty Guid as incomplete. Call stays version 1. Out of scope: Low tab
  (T-5.1.4), break prompts (T-6.5.1), replacements (E10), "Outside your ranges" (S5, E9), S9, S13.
- **D10 Finish:** push, PR, merge after CI (merge commit, branch kept), update local main.
