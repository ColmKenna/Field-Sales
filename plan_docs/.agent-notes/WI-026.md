## Inspection findings and proposed interpretations

- Existing /coverage/locations/{id}/owner and /history reads deny unassigned or foreign-team Locations to Sales Managers. Existing characterization tests explicitly require this behavior. Rep lists and mutations also depend on team authorization. The new slice explicitly says a manager opens “any shop”.
- Proposed (inferred, accepted with this plan): add a separate narrowly scoped, read-only Location coverage page contract/endpoints available to current Sales Managers and Head Office, including other-team and unassigned shops. Return only Location/Town context, computed owner/source and captured assignment-history data. Preserve existing owner/history endpoints, rep books, team-scoped choices and every mutation restriction. Do not widen Head Office directory/master-data access. Field Salespeople and SysAdmin alone cannot use the new view. This isolates the new visibility requirement without invalidating approved WI-021 behavior.
- Current coverage owner contract has an opaque rep subject, not a trusted rep display label. Use existing CoverageStaffProvider server-side trusted staff data outside SQL locks, then read coverage consistently in a serializable business transaction using the single EffectiveOwnerResolver. Identity failure must never appear as Unassigned. Existing inactive owners remain visible with trusted labels; do not apply recipient eligibility to a read.
- Historical labels are captured snapshots and must survive staff/geography renames. Existing AssignmentHistoryFormatter.Display has extra cause text and an explicit UTC suffix. Keep that existing contract and all history writes unchanged; a new presentation formatter over captured fields will supply the required example wording, preserve reasons and distinguish direct assignment/geography change. Retain explicit UTC because no business-local timezone has been approved.
- (Inferred) Until WI-027, show native disabled Assign Town / Assign just this shop affordances with concise unavailable guidance, rather than a save handler or nonexistent link. Where shown, the other-unassigned-Locations-in-Town count comes from the existing resolver, excludes the current shop and uses singular/plural correctly. Actual assignment/change/transfer-from-shop behavior remains WI-027.
- (Inferred) Provide a stable /Coverage/Location/{id} page and History back navigation, link direct-Location assignment rows on the Territory page and the existing Head Office Location detail. Inherited Location discovery through the future unassigned list remains WI-028; no new search/list product is added.
