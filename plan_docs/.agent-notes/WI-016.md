## Authorization and decisions

The developer approved the plan and scenario list on 2026-10-02. Before approval
they chose **Require a first Location when creating a Customer**. Customer and
first Location must save atomically; missing/invalid first Location saves neither.
Additional Locations are added from the Customer record.

Approved defaults: names are required, trimmed, max 200 characters; Location
duplicate checks ignore case within one Customer and apply to creation and
renaming; Customer names remain nonunique. Eircode is optional text; lookup and
coordinates are WI-019. New references require an active full geography path;
existing archived references survive unrelated edits as decided in WI-015.
