### Decided — previous snapshot generations

Code evidence: `SnapshotStore` retains two completed generations (`RetainedGenerations`); activation
retires only older generations, and background cleanup removes retired rows. Active readers always join
the `active` pointer. Thus after a successful removal Sync, T1 proves no current UI/read exposure, but
the previous authorized generation can still contain the product in local storage. The completed
download file is deleted by TabletSync; captured order lines are separately retained intentionally.

The developer explicitly selected **A — restrict active reads; keep recovery snapshots**:

- **A — active catalogue and new downloads:** preserve the existing two-generation recovery policy.
  T1 checks current reads; no assertion that older recovery copies are erased. This is an explicit
  scope decision against the source phrase absent entirely, not an inferred permission.
- B (purging older catalogue copies on access reduction) was not selected. No storage amendment or
  erasure test is part of this item. Failed-Sync atomic recovery remains covered by T2.
