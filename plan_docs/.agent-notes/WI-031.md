## Approved design and criterion amendment

- MI-44 is resolved for this item's message: keep an accurate rep count, omit order-line counts.
  It remains a separate question for other work items. The original CV009-E/F numeric order-line
  messages are superseded by the developer's choice; do not edit console card/story content.
- Single: **Colm will lose Pharmacy-only medicines at his next Sync. Any lines already on unsent
  orders will still send.**
- Cohort: **3 reps will lose Pharmacy-only medicines at their next Sync. Any lines already on
  their unsent orders will still send.** One message for the whole action.
- **Remove → Review → Confirm removal / Cancel.** Review and Cancel write nothing. Reason is
  optional under existing validation and bound into the review, rather than editable at confirmation.
- A protected BFF review binds the actor, group, selected reps, last-change ids and reason, expiring
  after 30 minutes. Confirmation uses that reviewed command. Missing/altered/expired/foreign-actor
  confirmation is rejected; stale permission requires a fresh review.
- Preserve existing API authorization and writer. The review is the website interaction; direct
  authenticated business API operations retain the existing authorization/current-state checks.
- Archived wording says it already grants no access and restoring the group will not restore a
  removed permission. Existing removal eligibility for inactive holders remains.
