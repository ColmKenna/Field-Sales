## Approved decisions

The developer accepted these policies with **Approved** on 2026-10-03.

1. **Compute owners on read** using one pure resolver and batched queries rather
   than maintaining an owner cache. Future snapshots consume the same resolver.
2. **Record inherited ownership on Location creation:** when assigned, write
   Unassigned → resolved rep in the creation transaction. A Location created
   Unassigned has no ownership-change entry. Apply to first and later Locations.
3. **History:** append-only entry per changed Location, previous/new rep identities,
   actor identity, UTC timestamp displayed to the minute, source assignment/level/unit,
   cause and optional reason. Preserve display labels for a readable historical
   record. Reserve `geography change` alongside `direct Location assignment` and
   `territory assignment`; later cards own batch/specialist behavior. Source-only
   changes with the same effective rep do not produce an ownership-change entry.
4. **Reporting-line source — decided:** the developer answered **Store reporting
   lines in Field Sales business data, managed by Head Office** on 2026-10-03.
   This is recorded in `decisions.md`. Exactly one manager per rep; Head Office
   may act on any rep. No guessed team, hard-coded subjects or authority from
   browser input.

Approved concrete implementation of that decision:
`RepReportingLine` in DirectoryDb, keyed uniquely by the rep's identity subject,
with the manager's identity subject and concurrency version. A narrow Head Office
reporting-line page lists eligible staff from a read-only identity lookup and
selects the manager for each rep. Reuse existing identity accounts/roles; do not
create accounts, edit roles, copy credentials or add cross-database foreign keys.
The trusted identity read contract exposes subject, display label, current
business roles and account availability only; reject missing/ineligible subjects
and fail closed on lookup failure. API filters manager-visible rows by business
reporting lines, and Head Office sees all. Current-role checks remain mandatory.
