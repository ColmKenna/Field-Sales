## Approved decisions

- **D1 Category override (MI-47):** not built; criterion 5 reported as decided against.
- **D2 Storage holds terms only:** `PriceTiers` (name, default %) and `PriceTierOverrides` (tier, product, a % or a fixed price; one
  per product per tier). No resulting prices stored.
- **D3 Where (inferred):** in the catalogue database beside Products, with a foreign key to the product.
- **D4 Limits:** default and override % more than 0 and less than 100, 2 dp; fixed more than €0.00, to the cent; tier name required,
  unique ignoring case, at most 100 characters (inferred).
- **D5 Editing:** rename, change %, add/change/remove overrides; no delete; the last save wins (inferred).
- **D6 Override rows:** term, list price and today's price (engine, business day, never stored); detail leads with overrides
  (H20.1); default shown as "8% off base"; no customer count until T-6.2.1.
- **D7 Picking:** search on the tier page with the existing product search; matches show code, name and list price; products
  already overridden are marked.
- **D8 For WI-157 (inferred):** each override records the business day it was last set (a date, not a price).
- **D9 Access:** Head Office User only (new API policy like `HeadOfficeCatalogue`; website's HeadOfficeUser policy); a "Price tiers"
  link on the head office index.
- **D10 Out of scope:** price-list tiers, above-list warning, shape change (T-6.1.2); assignment and customer counts (T-6.2.1);
  drift (WI-157); tiers in the snapshot; promotion audiences.
