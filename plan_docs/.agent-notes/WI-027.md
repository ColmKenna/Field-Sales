## Inspection findings and proposed interpretations

- WI-026 LocationCoverageReader already resolves owner/count through EffectiveOwnerResolver in a serializable business snapshot. Its page contract exposes source target/name, but no source assignment ID or whole-source Location count. Keep the existing read contract intact and add a focused action-context read with the same page snapshot plus exact source assignment ID/count and action availability. This metadata is a navigation aid, never a write grant. Staff labels remain trusted, acquired before SQL locks.
- Reuse TerritoryAssignmentStore PreviewAdd/SaveAdd and AssignmentTransferStore Review/Preview/Save. Existing proof binds actor, command, current roles/team/geography/assignments; explicit confirmation is mandatory and stale snapshots refresh for another confirmation. History is atomic and captured by the existing writers. No ownership resolver, Add/Transfer policy or schema change.
- (Inferred) Introduce a focused LocationChange Razor entry page for action intent, eligible recipient and optional reason. Derive Town/Location/source targets from fresh server context. Free or inherited single-shop assignment uses the existing Add preview/save plus shared _AssignmentImpact. An already-direct Location assignment uses existing exact-assignment Transfer, preserving assignment ID. Source transfer enters the existing Transfer page restricted by exact assignment ID, not a name filter or the giver's whole book; preserve County/Region exclusions and rollups.
- (Inferred) Covered County/Region sources receive the same secondary transfer affordance, accurately named by level/geographic Location count. Already-direct coverage offers just the single-shop change, since a second source-transfer button would duplicate the same operation. Source footprint includes all geographic Locations, while preview's changed-owner count respects existing narrower assignments. Future Locations follow transferred territory assignments.
- Existing managers may read any shop via WI-026, but mutation authority comes from existing API rules. Add permits an authorized recipient to receive a narrower direct assignment over inherited coverage; it does not separately require management of that inherited owner. Transfer and same-level held targets check the source and recipient. Preserve this existing distinction; do not silently introduce a global foreign-inherited-owner prohibition or relax direct-assignment/source-transfer restrictions. Head Office retains its existing wider authority. Current role/reporting-line changes are rechecked at every mutation.
- Existing Add choices require active Field Salesperson; manager choices are their current team. Transfer also requires the recipient's reporting line even for Head Office. Existing inherited/inactive owners remain readable; existing archived-source transfer behavior remains unchanged, whereas new Add targets must meet current geography activity checks. Do not unify these different established eligibility rules.
- (Inferred) Action availability respects exact target/source and existing authority; unavailable actions have meaningful guidance, including no eligible recipient. Invalid/tampered entry context cannot broaden selection. Cancel and successful save return to the original known Location route with a notice, never an arbitrary URL. General Assignments/Transfer journeys keep their existing navigation.
- Required “Town already held” edge: an authoritatively unassigned shop cannot simultaneously inherit an assigned Town. Treat it as a stale page: Town assigned before action/preview. Proposed outcome (inferred, accepted through plan approval): report changed coverage and require a fresh Location review; do not silently turn Assign Town into a whole-Town transfer. Existing reviewed stale-preview refresh still applies where the chosen operation/scope is unchanged.
- (Inferred) When Walsh's is the only unassigned shop, keep Town-first and just-shop actions; omit the zero-neighbour sentence. Singular count uses “1 other Location ... is unassigned”; four uses the exact source criterion (without inserting “also”). Counts come from resolver, excluding this shop and respecting direct overrides.
- Existing same-owner/source-only/no-history standing decision remains authoritative. Exclude current owner from covered-change recipients rather than offering a meaningless owner change; unchanged effective owners in wider transfer produce no fabricated ownership history.
