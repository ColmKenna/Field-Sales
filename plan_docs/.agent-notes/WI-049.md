## Approved decisions

- **D1:** add `OrderLifecycleStatus.Accepted` with no transition; "Ordered recently" uses Accepted orders only. Real lists show only
  "Last visit" until WI-067. Tests seed Accepted orders.
- **D2 (MI-12 stopgap):** API option `TabletSnapshot:SuggestedListOrderCount`, default 3, validated 1–10 (range inferred), configuration only.
- **D3:** snapshot 1.3 (minor): two optional families of (locationId, productId) rows — last stock check lines and products on the last N
  Accepted orders — filtered server-side to the rep's Locations and visible products. The tablet merges them (one function). Older apps ignore.
- **D4:** server tables `ReceivedCalls` + `ReceivedCallStockEntries`, written in the Call's receive transaction. Last stock check = the
  Location's latest In-person Call with stock entries, by SavedAt (tie: id). No backfill.
- **D5:** stock check hidden on Phone; counts stay in the draft if switched back; a Phone call saves no stock entries (T-5.3.2 later).
- **D6:** all-Not-checked does not count as recorded ("Add pitch notes, a stock check or a competitor note").
- **D7:** typed count + −/+; negative "Enter 0 or more"; fraction on Each "Enter a whole number" (inferred wording); measures up to 6 dp with unit.
- **D8:** labels "Last visit", "Ordered recently", "Last visit · Ordered recently"; header/review "10 counted, 3 not checked" ("13 counted"
  when all counted); empty "No suggested products yet — search or browse to add"; rows sorted by name (inferred).
- **D9:** stock entry = productId, productCode, productName (as captured), unit, count (null = Not checked). Removed rows not saved.
  Reserved per-entry `low` absent until T-5.5.1.
- **D10:** checkpoint size check = desktop measurement at target scale (download size, import time vs. current). No device timing.
- **D11:** finish = push, PR, merge after CI (merge commit, branch kept), update local main.
