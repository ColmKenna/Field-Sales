### Explicit proposed interpretations (inferred; approval adopts these)

- Roll-ups produce a minimal new assignment set: move the parent and preserve earlier carve-outs, without creating redundant child rows for the same recipient. Existing separately selected direct child assignments retain their IDs and move too.
- Count every geography child, including zero-shop and archived children, according to its effective territory assignment rather than only counting changed Locations. A narrower explicit Town/County assignment excludes that unit from the parent's held-child set; a direct Location exception does not remove the whole Town/County from it.
- Transfer can move existing coverage on archived geography and from an inactive giving rep with a trusted identity. This is a transfer-specific rule, not a change to the active choices/eligible recipient restrictions of Add assignment. Geography flags never change. New partial carve-outs represent a transfer of existing inherited coverage, including archived child units.
- Whole-parent selection preserves narrower assignment records unless they are separately selected. Child exclusions demote a parent to selected children; they do not move the parent while claiming its excluded children stayed behind.
- Manager access must cover both giving and receiving rep under the existing reporting-line authority. Cross-team cover's separate permission exception does not apply.
- History cause is per changed Location, so a mixed transfer may contain both existing cause values under one operation ID. No new cause enum or schema is needed.
