## Approved plan

1. Call model: new project `FieldSales.Calls.Contracts` (records + source-generated JSON, like `Ordering.Contracts`) in `FieldSales.slnx`
   and `FieldSales.Tablet.slnx`; Tablet Core `CallStore.Save` (snapshot ref, rep, local date; one id per page; no update method) and a
   shared check/summary rule; server `TabletWorkReceiver` structure checks (unsupported / incomplete / not-yours). Calls stay in
   `ReceivedWork` only. **CHECKPOINT.**
2. `RecordCall.razor` at `/locations/{id}/calls/new`: HOW with two large unselected toggles, collapsed Pitch notes, Review and save.
   Location screen's Record Call navigates there.
3. Save review dialog: "Save this call?", one-line summary, Back / Save. Back to shop with "Call saved. It goes to head office at your next Sync."
4. Checks inline; draft kept in app memory per rep/session/shop (survives resume rebuild); leaving with content asks "Leave without saving
   this call?" (Leave / Stay). Unsent review shows "In person"/"Phone".
5. Agreed tests, full suite, console tests, Android build, `docs/tablet-call-recording-delivery.md`, status done, push.

Body (v1): `schema "field-sales-call"`, `version 1`, `id`, `locationId` (top level: retention reads it), `capturingRep`, `calledOn`,
`savedAt` (local with offset), `channel` InPerson|Phone, `snapshot {version, builtUtc}`, `pitchNotes` (absent when none).
Reserved optional sections (D5): `stockEntries[]` (T-5.4.1/T-5.3.2, with per-entry `low` for T-5.5.1), `competitorNotes[]` (T-5.8.1),
`followUpOf` (T-5.7.1), `campaignOutcomes[]` (E20), `rangeReview{}` (E23; purposes derived from sections present). Visit Due completion
(E13) needs no field.

Existing tests that change on purpose (they pin the lenient Call acceptance or the stub): `TabletWorkPayloadTests.Should_AcceptTheCall_...`,
the Call cases in `TabletUploadApiTests` (stored once; id mismatch; "another kind" with a real body keeps 409), `TabletUploadEndToEndTests`
(real Call), `LocationDetailComponentTests` "Record Call isn't available" row.
