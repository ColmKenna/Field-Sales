## Approved plan and decisions

1. Add archive state and an additive DirectoryDb migration.
2. Reuse reference usage interfaces and retirement policy; transactional usage
   recheck prevents deleting newly used rows.
3. Reuse shared usage/action and confirmation controls on geography, preserving
   its hierarchy, creation, renaming and CSV flow.
4. Filter archived geography from new choices and supply existing-reference labels.
5. Run characterization checks first, then focused and complete suites, commit
   scoped changes and push the feature branch.

Archive changes only the selected row. Archived County/Region ancestors exclude
descendant Towns from new choices without changing child archive flags. Existing
links remain intact; archived children still count. Un-archive restores choices
only under an active hierarchy. CSV never reactivates existing places. New children
under an archived ancestor are rejected and the entire import rolls back.

Location storage/forms belong to WI-016. Until then there are no production
Location records; the four-Location scenario uses a test usage source. WI-015
provides the usage and existing-reference contracts; WI-016 must connect real
Location counts, transactional assignments and existing-reference display.
